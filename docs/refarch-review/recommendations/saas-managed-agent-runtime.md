# Review: API/SDK managed agent runtime

> **Status (2026-09-01): APPLIED** on branch `refarch-review-updates`. Every finding was
> executed per its Second-review verdict — Agree rows as written, Modify rows as amended,
> Disagree rows via the stated alternative — with guidance updated in the same commits.


Files reviewed: `data/reference/architectures/saas-managed-agent-runtime.yaml` and its paired guidance.

## Overall assessment

The hybrid build/configure framing is sound. The file currently combines incompatible provider variants: it says platforms supply first-class per-agent identity while its graph and risks say no agent principal exists, and it says the customer owns a front end that is not drawn.

## Preserve

- Keep this separate from low-code because the authoring and delivery controls differ.
- Keep vendor runtime opaque, customer definition/code, customer gateway, internal tool services, and enterprise data as the main responsibility boundary.
- Keep memory scope, agent identity, trace export, and portability/opacity as explicit adoption decisions after resolving product variants.
