# Review: Local model runtime

> **Status (2026-09-01): APPLIED** on branch `refarch-review-updates`. Every finding was
> executed per its Second-review verdict — Agree rows as written, Modify rows as amended,
> Disagree rows via the stated alternative — with guidance updated in the same commits.


Files reviewed: `data/reference/architectures/endpoint-local-inference.yaml` and its paired guidance.

## Overall assessment

This is appropriately small and clearly distinguished. Its largest error is the model-acquisition control: scanning cannot happen before bytes are fetched, and a target-state runtime should not fetch and immediately load untrusted artifacts in one step.

| LI-10 | Judgement | Low | API/runtime boundary | The target requires authentication and guardrails, but it is ambiguous whether `Inference API` is the raw runtime endpoint or an organisation-operated wrapper. | Define it as an authenticated policy wrapper in target state, with the raw runtime API private behind it; otherwise draw the reverse-proxy/policy component that actually runs. | **Agree** — vocabulary.yaml defines Inference API as the raw published endpoint whose "defining property ... is that authentication is optional and usually absent", so the target-state auth and guardrail claims need a drawn or explicitly-absorbed wrapper. ## Preserve

- Keep this separate from self-hosted cloud inference; the operational boundary materially changes the design.
- Keep API, runtime, weights, and source hub as distinct concepts.
- Keep parser/deserialization, exposed-port, denial-of-service, model-behaviour, and unknown-runtime risks after correcting their control loci.
